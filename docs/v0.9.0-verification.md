## WP1 — theme and typography

- `layoutCss.ts` exposes `typographyOverrides`, `buildLayoutCss` and
  `buildExportLayoutCss`; no `!important` is needed for settings.
- Tokens: `--tl-body-font`, `--tl-code-font`, `--tl-editor-bg`,
  `--tl-line-height`, `--tl-paragraph-gap`, `--tl-list-marker`,
  `--tl-ordered-marker`; attributes include `data-direction`,
  `data-heading-numbering`, `data-tl-justify`, `data-tl-font`, etc.
- Typography settings are three-state: follow theme (default), built-in, or an
  explicit value; a ↺ button restores “follow theme”. Only explicit values emit
  CSS.
- HTML/print export wraps content in `#write` and inlines the active theme CSS
  plus token overrides. Pandoc exports map font/font-size/direction variables
  where the target supports them.
- Theme debug panel shows the active theme, transformed size, blocked external
  resources and the source of each typography value.
- `docs/theme-authoring.md` and `docs/theme-authoring.zh-CN.md` document the
  current contract; README (both languages), Settings → Theme and the old
  compatibility note link to them.

**Tests:** `layout` asserts RTL/body font/background/justify/markers/heading
counter/code font plus the new attributes and token variables; `settingstype`
asserts the three-state controls and that a custom body font is persisted;
`exporttheme` asserts `#write` wrapping and theme CSS in generated HTML.

## Known limitations

- LaTeX delimiters are normalized to `$`/`$$` on save; original `\(`/`\[` style
  is not preserved.
- Pandoc formats cannot inherit the full CSS theme; only font/size/direction
  variables are mapped.
- The TOC node refreshes on an 800 ms interval while mounted.
- Real Typora theme/print fidelity and Mermaid diagrams still need manual checks
  on each platform.
